## 핵심 설계 결정 (왜 이렇게)
- **부대 = 장수 1명 + 그 장수의 병력.** 병력·훈련도가 장수 단위(Day 6 모델)라 이동 = 장수 이동,
  병력은 장수를 따라간다. → 별도 "병력 split" 없음.
- **이동 중 장수는 출발지에서 분리(`region=nil`).** 그래야 출발지 active 카운트에서 빠지고
  "출발지 0명 → 중립 강등(`demoteIfVacant`)"이 자연히 작동. 도착 시 `region=목적지`로 갱신.
- **"남은 병력 0 해산"은 자동.** 병력이 장수에 붙어 있어 장수가 다 떠나면 그 지역 병력은 자동 0
  (버릴 병력이 따로 없음). GDD 문구는 풀(pool) 모델 기준이라 명시된 것.
- **병력 합류 = `mergeTraining` 재사용.** 도착지에 친군 수비 지휘관(태수 우선)이 있으면 그쪽으로
  병력 합산 + 훈련도 가중평균(징병과 동일 공식) → 지역 병력은 한 부대로 통합, 이동 장수 병력 0.
  친군이 없는 중립 지역이면 합류 대상이 없으니 이동 장수가 병력을 쥔 채 **무혈 입성**(소유권 이전).
- **인접 판정은 주입.** `movement`는 지도/좌표를 모름(love·hex 비의존 유지) → `main`이
  `Region.areAdjacent`를 `isAdjacent` 함수로 끼워준다(의존성 역전, 테스트는 가짜 함수 주입).
- **적 지역 진입은 차단.** `canMove`에서 타 세력 소유지는 "전투 미구현"으로 막음(GDD 13장 다음 작업).

## 도착 처리 흐름 (GDD 3장 2번 → 12장)
- `advanceTurn` 순서: 턴종료 → **도착(onArrivals)** → 성장 → AI → 날짜+1 → 수확 → 리셋.
- `onArrivals`는 날짜 진행(count+1) **전**에 불리므로 `arrivingCount = turn.count + 1`을 넘김
  → `arriveTurn <= arrivingCount`인 명령 전부 처리·목록에서 제거(다음 턴 도착 = 턴 종료 직후 반영).
- 명령 생성 시 `arriveTurn = turn.count + 1`로 고정(거리 무제한이라 항상 다음 턴 도착).

## 수송 (GDD 12장)

## 핵심 설계 결정 (왜 이렇게)
- **유닛 = 장수 1명(그 장수 병력).** "데려간 장수 수만큼 유닛"(GDD 13장). 출진 = 그 지역 active·병력>0 장수 전원.
- **병력 = HP(내구도), 무력+훈련도 = 공/방 품질.** 병력을 HP 로 두어 '투입 병력'이 지속력으로 작동 → 스탯 이중계산 방지.
  유효무력 = `effectiveStat`(장비 보너스 포함, GDD 8장).
- **승패는 전멸로만**(GDD 정정). 후퇴 없음. ESC 는 선택 해제/결과 확인만(맵으로 안 튐).
- **데미지 = max(minDamage, floor(공격-방어)).** 방어 높아도 최소 데미지 → 교착 방지.
- **전술 AI 최소 휴리스틱**: 가장 가까운 적으로 그리디 이동 후 사거리 내면 공격. 결정적(시드 고정 테스트). 정교화 금지(스코프 락).
- **인접 판정 주입**(`isAdjacent`) — battle 은 지도/좌표 모름(love·hex 비의존, 테스트 가능). main 이 `Region.areAdjacent` 끼움.
- **결과 반영(resolve)**: 잔여 HP→병력 기록. 승=소유권 이전+생존 공격 장수 점령 입성(전멸 공격 장수는 출발지 패주),
  방어 장수 전원 보드에서 내려 포획 훅(`onCaptured(region, atkFid, defenders)`)으로 전달(D4). 패=공격 장수 출발지 복귀(병력 손실).
  양 지역 `demoteIfVacant`(정합성) + `assignGovernor`(태수 재선정) 재사용.
