# 추가 작업 — 2026-06-13 (외교) — 적대치 시스템 (GDD 6장)

## 변경 내용

## 핵심 설계 (왜)

- **단계(tier) → 수치 변환 단일 지점**: 시나리오 데이터엔 `"hostile"` 문자열만 기재. 수치(85)는 `config.hostility.tier`에서만 조회 → 수치 변경이 config 1곳만 수정.
- **미기재 쌍 = 중립(50) 기본값**: 적대 관계는 명시만 기록. 명시 없는 쌍은 자동으로 neutral → 데이터 파일이 불필요하게 커지지 않음.
- **nil 반환 의미론**: 본인 소유 지역·중립 지역은 수치 없음(`nil`). UI는 nil → `"-"` 출력. numeric 0(동맹) vs nil("해당 없음") 구분 → 의도적 트레이드오프.
- **비대칭 구조 허용**: A→B 와 B→A 를 각각 기재. 역사적으로 단방향 적대가 존재(GDD 6장). 현 시나리오는 대부분 대칭이나 구조적 비대칭 지원.
- **시나리오별 역사 근거**:
  - 184(황건난): 황건적이 모든 제후와 적대. 제후 간 관계는 아직 미결 → 나머지 미기재.
  - 194(군벌할거): 원소↔공손찬(하북), 조조↔원술·도겸·이각곽사(중원), 손책↔원술·유표(강남), 유장↔장로(서천) — 실제 영토 분쟁 쌍만 기재.
  - 221(삼국정립): 위·촉·오 전 쌍 상호 적대 — 이미 봉합 불가 전쟁 상태.
- **AI 활용**: `getHostility` 반환값 > `config.ai.attackHostilityThreshold` 이면 공격 후보에 편입 (GDD 16장 `AI.run` 공격 조건).
