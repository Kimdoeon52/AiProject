## 핵심 설계 결정
- **병력·훈련도는 수행 장수 단위.** region엔 troops 필드 없음(정보팝업이 장수 합산 표시), 한도(무력*5)도
  장수별 → 훈련도도 `officer.training`(신규)에 둠. GDD "지역 병력/훈련도"는 수행 장수의 troops/training으로 매핑.
- **행동완료 = 기존 `officer.actionDone` 재사용.** `advanceTurn`이 이미 `resetActions`로 리셋 → advanceTurn 미수정.
  "지역당 턴 1회"는 지역 내 행동 가능 장수가 없으면 버튼 비활성으로 충족(통상 지역당 1장수).
- **계수는 config 상수 + GDD 11장 밸런싱 주석**(economy/gift 선례). GDD 11장은 정성만 명시, 정량은 코드에.

## 징병 (GDD 11장)
- `applyRecruit`: 한도 클램프 `add = min(troopsPerAction, cap - troops)` → 금 -70 → 인구 -floor(add*0.02),
  민충성 -3 → 훈련도 가중평균 `(old*training + add*0)/(old+add)`(0나누기 가드) → troops 충원 → `markActed`.
- `canRecruit`: canAct + 금 충분 + 병력 한도 미달.

## 훈련 (GDD 11장)
- `applyTrain`: `gain = 무력 * 0.1` → `training = min(100, training+gain)` → `markActed`.
  무력100 → +10/회 → 10회로 100, 상한 클램프.
- `canTrain`: canAct + 병력>0 + 훈련도<100.

## UI 흐름
- 패널 버튼(위→아래): 징병 / 훈련 / 정보확인 / 장수확인 / 턴종료.
- 활성: 선택 + 플레이어 소유(`ownership[sel]==playerFactionId`) + 행동 가능 장수≥1. 아니면 회색 DISABLED.
  (코드베이스 비활성 스타일은 회색 — "빨간 비활성"은 이를 가리킴, 일관성 위해 재사용.)
- 클릭 → `state.action="recruit"/"train"` → 수행 장수 선택 모달(병력 N/한도·훈련도 표시, 불가 장수 비활성).
- 장수 클릭 → game_state 규칙 수행 → `notice` 결과 표시, 팝업 유지(행동한 장수 비활성화). ESC/X 닫기.
- 자원 변화는 `regionState` 직접 읽어 패널 즉시 반영.
